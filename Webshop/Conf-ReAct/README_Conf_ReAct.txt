================================================================================
Conf-ReAct — WebShop Reproduction Guide
================================================================================

"Conf-ReAct" (this folder) = conformal-guided BFS planning for WebShop:
each step samples candidate actions from the LLM, scores them with a trained
score model, keeps a conformal prediction set of the most-plausible ones (dual
LP, Gibbs et al. 2023), and expands all of them breadth-first.

This is a self-contained pipeline: data -> train score model -> conformal BFS
search -> evaluation. Every script's paths already point inside this folder
(no other checkout is required). It assumes the WebShop server is already
running — see ../README.txt Section 1 for that setup; it is identical here.

Layout
    README.txt                            this file
    WebShop_ScoreFunc_Train_Data.csv       training / calibration data (shipped)
    score_model_webshop.py                 score-model architecture + BERT cache
    train_score_webshop.py                 Stage 1: train the score model
    conformal_predictor_webshop.py         dual-LP conformal predictor
    conf_react_webshop.py                  Stage 2: the Conf-ReAct search itself
    webshop_reflexion_selfset.py           Stage 3a helper: log reconstruction
    webshop_reflexion_selfset_3trials.py   Stage 3a: baseline self-sized-set generator
    fraction_of_states_vs_prediction_set_size.py   Stage 3b: the set-size figure
                                            (also carries the shared BFS-log/CSV
                                            parsing helpers used by 3a and 3d)
    count_llm_calls_winning.py             Stage 3c: LLM-call accounting
    count_llm_calls_winning_allmodels.py   Stage 3c: LLM-call accounting, all 3 models
    table_coverage_vs_setsize_webshop.py   Stage 3d: empirical coverage table
    logs/                                  put your run transcripts/CSVs here (empty; see Stage 2/3)

Not included: the trained score-model checkpoint and its BERT embedding cache.
Both are regenerated by Stage 1 (Section 2). The cache is a dict of one 768-dim
CLS embedding per unique instruction/action string seen in the training CSV —
tens of thousands of entries, but each embedding is cloned before caching (see
the comment in score_model_webshop.py), so a freshly-trained cache lands
around 10-15 MB, not gigabytes.


================================================================================
1. PREREQUISITES
================================================================================

  - A running WebShop server (see ../README.txt, Section 1).
  - An open-weight model served via vLLM, OpenAI-compatible endpoint:
        vllm serve Qwen/Qwen2.5-3B --port 8000
  - Python packages: torch, transformers, numpy, scipy, requests,
    beautifulsoup4, openai, matplotlib
  - A local (or cached) copy of "bert-base-uncased" for the score model's
    frozen BERT encoder (downloaded automatically by `transformers` on first
    use if you have internet access).

All models used in this pipeline are open-weight and locally served; no
hosted/commercial API is involved anywhere below.


================================================================================
2. STAGE 1 — TRAIN THE SCORE MODEL  (train_score_webshop.py)
================================================================================

Loads WebShop_ScoreFunc_Train_Data.csv, computes a frozen-BERT CLS embedding
for every unique instruction/action string seen in it (this IS the "compute
embeddings" step — it happens in-process, there is no separate script for it),
builds (state, action, label) pairs, and trains the score-function MLP.

    python train_score_webshop.py
    python train_score_webshop.py --epochs 150 --batch_size 64 --lr 0.001

Options:
    --data PATH        training CSV        (default: the shipped CSV, this folder)
    --epochs N          (default 150)
    --batch_size N      (default 64)
    --lr F              (default 1e-3)
    --val_split F       (default 0.2)
    --patience N        early-stopping patience (default 15)
    --seed N            (default 42)

Output, written to ./trained_models_webshop/:
    best_score_model_webshop.pt    score-model checkpoint (best val loss)
    bert_cache_webshop.pkl         BERT CLS-embedding cache (see size note above)
    loss_curve_webshop.png         train/val loss curve

conf_react_webshop.py (Stage 2) reads its checkpoint and BERT cache from this
exact directory — nothing to move or rename.


================================================================================
3. STAGE 2 — CONFORMAL BFS SEARCH  (conf_react_webshop.py)
================================================================================

This is the actual Conf-ReAct search script. Two things make it a "CSV-
instruction variant" rather than a plain episode-index loop:
  * Episodes are driven by (id, Original_instruction) pairs read straight out
    of WebShop_ScoreFunc_Train_Data.csv (via --n_episodes as a CAP on how many
    of those pairs to run), not by range(n_episodes).
  * At each episode start it prints BOTH the CSV-recorded instruction and the
    WebShop env's own instruction for that session id, tagged [MATCH] /
    [MISMATCH]. Mismatched episodes are SKIPPED by default — pass
    --include_mismatched to run them anyway.
The (id, instruction) pairs are also dumped to webshop_csv_instructions.json
in the current directory on every run (informational; not consumed elsewhere).

Per episode:
  1. Restore the WebShop session to a BFS node's state (O(1) deep-copy, no
     trajectory replay).
  2. Sample n_samples LLM completions -> candidate actions.
  3. Score each real-action candidate via token log-probs -> 10-bin softmax
     histogram -> the trained score model.
  4. Get the conformal prediction set (dual LP) over those candidates.
  5. Enqueue every action in the set as a child BFS node (breadth-first).
Stops on reward == 1.0 (perfect), or when the node budget / queue is exhausted
(best partial reward is kept).

Before running, edit the top of the file:
    WEBSHOP_URL = "http://<host>:3000"                       # your WebShop server
    MODEL_NAME  = "google/gemma-4-12B-it"                    # shipped default
    client      = OpenAI(base_url="http://<host>:8003/v1", api_key="EMPTY")
Commented-out lines right below MODEL_NAME/client switch to Qwen3-8B via vLLM —
uncomment those (and comment out the gemma line) to run that model instead.

Run (one alpha at a time), redirecting stdout — the evaluation stage parses
these transcripts directly. Note the shipped default alpha is 0.3, not 0.1:

    python conf_react_webshop.py --alpha 0.1 --n_episodes 200 > logs/bfs_webshop_conformal_0.1.txt
    python conf_react_webshop.py --alpha 0.2 --n_episodes 200 > logs/bfs_webshop_conformal_0.2.txt
    python conf_react_webshop.py --alpha 0.3 --n_episodes 200 > logs/bfs_webshop_conformal_0.3.txt

Options:
    --alpha F              miscoverage level (default 0.3 -> 70% target coverage)
    --k N                  top-k nearest calibration neighbours (default 50)
    --n_components N       SVD components for the dual-LP projection (default 10)
    --n_samples N          LLM free-samples per BFS node (default 10)
    --temperature F        LLM sampling temperature (default 0.7)
    --max_depth N          max trajectory depth per branch (default 15)
    --node_budget N        max BFS nodes per episode before giving up (default 100)
    --n_episodes N         cap on number of CSV ids to run (default 200)
    --include_mismatched   also run episodes where env instr != CSV instr (default: skip them)

To evaluate a second model (e.g. Qwen3-8B), edit MODEL_NAME/client above and
re-run with a distinguishing log name, e.g. logs/bfs_webshop_qwen_3_8b_0.1.txt
(this is the naming the evaluation scripts below expect by default).


================================================================================
4. STAGE 3 — EVALUATION
================================================================================

All four evaluation scripts read the raw transcripts / CSVs you produced in
Stage 2 from the ./logs/ folder (already wired as their default paths). Put
your files there under the names shown, or pass explicit paths via each
script's CLI flags.

--- 3a. Baseline self-sized-set generator (feeds 3b and 3d) ---------------------

Reconstructs each BFS-log state's prompt and asks the LLM for an unconstrained,
self-sized set of next actions (list-based Reflexion-style baseline, k<=3,
3 trials with self-refinement between trials) — this is the "ReAct/Reflexion
T1/T2/T3" series plotted in 3b.

Optional sanity check first (prints reconstructed prompts, makes no LLM calls):
    python webshop_reflexion_selfset.py --log logs/bfs_webshop_qwen_3_8b_0.1.txt --dump 2

Then generate the 3-trial CSV:
    python webshop_reflexion_selfset_3trials.py \
        --logs logs/bfs_webshop_qwen_3_8b_0.1.txt logs/bfs_webshop_qwen_3_8b_0.2.txt logs/bfs_webshop_qwen_3_8b_0.3.txt \
        --base_url http://<host>:8001/v1 --model_name Qwen/Qwen3-8B \
        --out_csv logs/webshop_reflexion_k3_3trials_qwen3_8b.csv

This writes ONE wide-format CSV (columns: instr, traj, size_t1, cov_t1,
size_t2, cov_t2, size_t3, cov_t3). Scripts 3b/3d expect three long-format
files instead (set_size,covered columns) — split it like this:

    python3 -c "
import csv
rows = list(csv.DictReader(open('logs/webshop_reflexion_k3_3trials_qwen3_8b.csv')))
for t in (1, 2, 3):
    with open(f'logs/webshop_reflexion_k3_trial{t}_qwen3_8b.csv', 'w', newline='') as f:
        w = csv.writer(f); w.writerow(['instr', 'set_size', 'covered'])
        for r in rows:
            w.writerow([r['instr'], r[f'size_t{t}'], r[f'cov_t{t}']])
"

--- 3b. The prediction-set-size figure (fraction_of_states_vs_prediction_set_size.py) ---

Absolute prediction-set-size distribution (bars) with per-alpha coverage
overlaid (line) — this is the exact figure format used in the paper. This
file also holds the shared BFS-log/training-CSV parsing helpers (CSV_PATH,
load_csv_lookup, parse_bfs_log, in_action_set, strip_price_clause, etc.) that
3a's scripts and 3d import — it is both the figure generator and the shared
parsing library for this stage.

    python fraction_of_states_vs_prediction_set_size.py \
        --logs logs/bfs_webshop_qwen_3_8b_0.1.txt logs/bfs_webshop_qwen_3_8b_0.2.txt logs/bfs_webshop_qwen_3_8b_0.3.txt \
        --baseline_csv logs/webshop_reflexion_k3_trial1_qwen3_8b.csv logs/webshop_reflexion_k3_trial2_qwen3_8b.csv logs/webshop_reflexion_k3_trial3_qwen3_8b.csv \
        --model Qwen3-8B --coverage

Defaults already point at the Qwen3-8B filenames above, so with those files in
place you can also just run:
    python fraction_of_states_vs_prediction_set_size.py --coverage

Key options:
    --logs PATH...          one BFS-conformal log per alpha (default: 0.1/0.2/0.3 above)
    --alphas F...            matching alpha values (default: 0.1 0.2 0.3)
    --baseline_csv PATH...  self-sized-set CSVs to overlay (default: T1/T2/T3 above)
    --baseline_label STR... legend labels (default: "ReAct/Reflexion T1", "reflexion T2", "reflexion T3")
    --bin_edges F...        absolute-size bin edges (default: 0 2 4 16)
    --coverage              draw the per-alpha coverage line (default: bars only)
    --model NAME            title / --out default tag (default: Qwen3-8B)
    --wide                  two-column-width figure instead of single-column
    --out PATH              output image (default: setsize_abs_distribution_coverage_webshop.png)

--- 3c. LLM-call accounting -------------------------------------------------------

Counts LLM calls spent on WINNING (score=1.0) episodes and reports the
average per win, including a node-count distribution for BFS-conformal wins
(one BFS node = one completions request that draws n_samples generations).

    python count_llm_calls_winning.py             # single model, edit BASE inside for other logs
    python count_llm_calls_winning_allmodels.py   # Qwen2.5-3B / Qwen3-8B / Gemma-4-12B side by side

Both scripts' __main__ hardcodes which filenames to read from ./logs/ (ReAct /
ReflAct / Reflexion baseline transcripts alongside the 3 BFS-conformal alpha
logs). Edit the filenames at the top of each __main__ block to match what you
generated, or symlink your files to the names already there.

--- 3d. Empirical coverage table --------------------------------------------------

Coverage% vs. absolute set-size bins (0-2, 2-4, 4-16), one row per method
(Conf-ReAct alpha=0.1/0.2/0.3, ReAct, ReflAct, GA-Rollback, and the T1/T2/T3
self-sized-set baseline), one column per model.

    python table_coverage_vs_setsize_webshop.py

Reads the MODELS dict near the top of the file (one entry per model, each
listing its conformal logs / react / reflact / rollback / trials paths under
./logs/) — edit that dict's filenames to match whichever logs you have.
Writes:
    coverage_vs_setsize_webshop.txt   human-readable table
    coverage_vs_setsize_webshop.csv   same, as CSV


================================================================================
5. END-TO-END SUMMARY
================================================================================

    1. python train_score_webshop.py
         -> ./trained_models_webshop/{best_score_model_webshop.pt, bert_cache_webshop.pkl}
    2. python conf_react_webshop.py --alpha {0.1,0.2,0.3} --n_episodes 200 > logs/bfs_webshop_conformal_0.{1,2,3}.txt
         (repeat with MODEL_NAME/client edited, per model you evaluate)
    3. python webshop_reflexion_selfset_3trials.py ...  -> logs/webshop_reflexion_k3_3trials_<model>.csv
         -> split into logs/webshop_reflexion_k3_trial{1,2,3}_<model>.csv
    4. python fraction_of_states_vs_prediction_set_size.py --coverage
    5. python count_llm_calls_winning_allmodels.py
    6. python table_coverage_vs_setsize_webshop.py
