================================================================================
Conf-ReAct — Game of 24 Reproduction Guide
================================================================================

"Conf-ReAct" (this folder) = conformal-guided BFS planning for Game of 24: at
each state (numbers left) the LLM samples candidate arithmetic moves, a
trained score model scores them, and a conformal prediction set (dual-LP,
Gibbs et al. 2023) restricts which moves get expanded. Game of 24 has a
perfect ORACLE (g24_oracle.py: every solvability-preserving move from a state
is computable exactly), so — unlike WebShop/ScienceWorld — ground-truth labels
never require replaying an LLM or an env; ground truth is exact and instant.

No server needed (same as Baselines/) — everything is local Python + a vLLM
endpoint. No hosted/commercial API is used anywhere.

Layout
    README.txt                       this file
    game24.py                        shared task environment (Game24Task)
    g24_oracle.py                    exact solvability oracle — ground truth
                                      for every move, used throughout Conf-ReAct
    game24_splits.json               the train/cal/test puzzle split
    sample_test_tasks.json           fixed 200-puzzle eval set (react_test split)
    prompts/game24_base_react.txt    few-shot prompt
    g24_data_generation.py           Stage 1: LLM rollout -> raw training pkl
    g24_compute_softmax_bins.py      Stage 2: raw pkl -> binned pkl (adds the
                                      10-bin softmax histogram feature)
    score_model.py                   score-model architecture + BertEmbeddingCache
    train_score.py                   Stage 3: train the score model
    conformal_predictor.py           dual-LP conformal predictor
    run_conformal_calibration.py     Stage 4: calibrate on held-out puzzles
    conf_react_game24.py             Stage 5: the Conf-ReAct search itself
    reflexion_selfset_3trials_game24.py   Stage 6a: self-sized-set baseline generator
    fraction_of_states_vs_prediction_set_size.py   Stage 6b: the set-size figure
    count_llm_calls_game24.py        Stage 6c: LLM-call accounting (per-α summary)
    count_llm_calls_winning_game24.py   Stage 6c: LLM-call accounting (winning-only)
    table_coverage_vs_setsize_game24.py   Stage 6d: empirical coverage table

Not included: trained score-model checkpoints, BERT caches, and the training
pickles. All are regenerated by Stages 1-4. Sizes seen in the source project:
best_score_model.pt ~7.3 MB (fine to ship, but omitted for a from-scratch,
code-only reproduction), bert_cache.pkl 17-43 GB per model (too large to ship
regardless — the cache is a dict of one BERT CLS embedding per unique
instruction/action string; large mainly because Game of 24 states/actions
combinatorially explode across 200+ puzzles).


================================================================================
1. PREREQUISITES
================================================================================

    vllm serve Qwen/Qwen3-8B --port 8002       # or Qwen2.5-3B / gemma-4-12B-it

Python packages: torch, transformers, openai, sympy, matplotlib, pandas, numpy


================================================================================
2. STAGE 1-2 — TRAINING DATA
================================================================================

Stage 1 (g24_data_generation.py) lets the LLM play from game24_splits.json's
puzzles, teacher-forced along an oracle-optimal path by default, and records a
training example (state, candidate actions + token log-probs, oracle labels,
optimal action) at every visited state:

    python g24_data_generation.py --split train --num_samples 20 \
        --n_samples 10 --policy oracle --out training_data_game24_train.pkl
    python g24_data_generation.py --split cal --num_samples 20 \
        --n_samples 10 --policy oracle --out training_data_game24_cal.pkl

Options:
    --num_samples N   number of puzzles from the split      (default 20)
    --seed N          puzzle-sampling seed                   (default 42)
    --n_samples N     LLM candidate samples per state         (default 10)
    --temperature F    (default 0.7)
    --policy          oracle | llm                             (default oracle;
                      oracle = teacher-forced gold path, llm = true rollout
                      that can walk into dead ends)
    --model_name / --base_url   vLLM endpoint
    --split           all | train | cal | test                 (default all)
    --splits_file      (default game24_splits.json, shipped here)

Stage 2 (g24_compute_softmax_bins.py) adds the 10-bin softmax histogram that
the score model consumes as its logit feature:

    python g24_compute_softmax_bins.py --in training_data_game24_train.pkl \
        --out training_data_2_game24_train.pkl --bins 10
    python g24_compute_softmax_bins.py --in training_data_game24_cal.pkl \
        --out training_data_2_game24_cal.pkl --bins 10

The "_2_" in filenames throughout this pipeline (and downstream defaults)
means "post-Stage-2 / binned" — train_score.py and run_conformal_calibration.py
both expect the Stage-2 output, not the Stage-1 raw pkl.


================================================================================
3. STAGE 3 — TRAIN THE SCORE MODEL  (train_score.py)
================================================================================

    python train_score.py
    python train_score.py --data training_data_2_game24_train.pkl --epochs 150

Options:
    --data PATH        (default: training_data_2_game24_train.pkl, this folder)
    --epochs N, --batch_size N, --lr F, --d_proj N, --hidden N, --val_split F, --seed N

Output, written to ./trained_models/:
    best_score_model.pt   score-model checkpoint
    bert_cache.pkl         BERT CLS-embedding cache (see size note above)
    loss_curve.png


================================================================================
4. STAGE 4 — CALIBRATE  (run_conformal_calibration.py)
================================================================================

    python run_conformal_calibration.py --alpha 0.1

Options:
    --alpha F     miscoverage level                    (default 0.1)
    --data PATH   (default: training_data_2_game24_cal.pkl, this folder)
    --out PATH    (default: calibrated_models/conformal_scores.pkl)

Reads ./trained_models/{best_score_model.pt, bert_cache.pkl} from Stage 3.


================================================================================
5. STAGE 5 — CONFORMAL BFS SEARCH  (conf_react_game24.py)
================================================================================

Per state: sample n_samples LLM candidate moves, union with the oracle's
complete correct-move set (--oracle_candidates, default on — matches how
calibration was built), echo-score every candidate's token log-probs, get the
conformal prediction set, expand only those children. Emits a
"[STATEMETRIC] set_size_pct=.. covered=.." line per state for the evaluation
scripts to parse, and stops a branch as soon as a leaf equals 24.

    python conf_react_game24.py --alpha 0.1 --max_puzzles 100 > compare_logs_100_qwen3_8b/m5_alpha01.txt
    python conf_react_game24.py --alpha 0.2 --max_puzzles 100 > compare_logs_100_qwen3_8b/m5_alpha02.txt
    python conf_react_game24.py --alpha 0.3 --max_puzzles 100 > compare_logs_100_qwen3_8b/m5_alpha03.txt

(create compare_logs_100_<model>/ yourself — mkdir -p compare_logs_100_qwen3_8b)

Options:
    --alpha F            label only — the threshold is baked into the calibrated pool
    --splits_file PATH    puzzle set to play         (default: sample_test_tasks.json, shipped)
    --split NAME          key within splits_file      (default "react_test")
    --scores PATH          (default: calibrated_models/conformal_scores.pkl)
    --model PATH            (default: trained_models/best_score_model.pt)
    --bert_cache PATH       (default: trained_models/bert_cache.pkl)
    --method              quantile | dual_lp           (default dual_lp)
    --n_samples N          LLM candidate samples per node   (default 10)
    --temperature F         (default 0.7)
    --oracle_candidates / --no_oracle_candidates   (default: on)
    --k N                  top-k calibration neighbours      (default 50)
    --n_components N        SVD components                    (default 10)
    --max_depth N            (default 10)
    --max_nodes N             (default 100)
    --max_puzzles N            (default 100)
    --base_url               vLLM endpoint
    --force_think / --no_force_think   include a "think:" step before each action (default on)
    --think_mode          forced | natural                     (default natural)
    --online_calib          fold each scored search state into the calibration
                            pool as BFS runs, attacking calibration/test
                            distribution shift (default OFF — the reported
                            results in this project use the default off; the
                            flag exists as a documented follow-up experiment)

MODEL_NAME/VLLM_BASE_URL for this stage are set in g24_data_generation.py
(imported by this script) — edit those constants, or the --base_url flag, to
point at your own vLLM server for a given model.


================================================================================
6. STAGE 6 — EVALUATION
================================================================================

Shared filename convention (all four scripts below read/write relative to
this folder):
    compare_logs_100_<model>/m5_alpha0{1,2,3}.txt     Conf-ReAct logs (Stage 5)
    compare_logs_100_<model>/base_react.txt           ../Baselines ReAct log
    compare_logs_100_<model>/base_reflact.txt         ../Baselines ReflAct log
    compare_logs_100_<model>/base_reflexion.txt       ../Baselines Reflexion log
    compare_logs_100_<model>/base_rollback.txt        ../Baselines GA-Rollback log
    reflexion_k3_trial{1,2,3}_<model>.csv             self-sized-set baseline (6a)
where <model> in {qwen25_3b, qwen3_8b, gemma4_12b}.

--- 6a. Baseline self-sized-set generator (feeds 6b and 6d) ---------------------

    python reflexion_selfset_3trials_game24.py \
        --logs compare_logs_100_qwen3_8b/m5_alpha01.txt compare_logs_100_qwen3_8b/m5_alpha02.txt compare_logs_100_qwen3_8b/m5_alpha03.txt \
        --base_url http://<host>:8001/v1 --model_name Qwen/Qwen3-8B \
        --out_csv reflexion_selfset_3trials_qwen3_8b.csv

Options: --k (max moves per self-sized set, default 8), --temperature (0.7),
--seed (1234), --chat (for instruct/chat models, e.g. gemma-it), --workers (16).

Writes ONE wide-format CSV (location,size_t1,cov_t1,size_t2,cov_t2,size_t3,cov_t3).
6b/6d expect three long-format files instead (set_size,covered) — split it:

    python3 -c "
import csv
rows = list(csv.reader(open('reflexion_selfset_3trials_qwen3_8b.csv')))[1:]
for t in (1, 2, 3):
    with open(f'reflexion_k3_trial{t}_qwen3_8b.csv', 'w', newline='') as f:
        w = csv.writer(f); w.writerow(['set_size', 'covered'])
        for r in rows:
            w.writerow([r[1 + 2*(t-1)], r[2 + 2*(t-1)]])
"

--- 6b. The prediction-set-size figure -------------------------------------------

    python fraction_of_states_vs_prediction_set_size.py --coverage
    python fraction_of_states_vs_prediction_set_size.py \
        --logs compare_logs_100_qwen25_3b/m5_alpha01.txt compare_logs_100_qwen25_3b/m5_alpha02.txt compare_logs_100_qwen25_3b/m5_alpha03.txt \
        --model Qwen2.5-3B --coverage

Ground truth here is entirely IN-LOG (the [STATEMETRIC] lines from Stage 5) —
no CSV/oracle lookup needed, unlike WebShop.

Key options:
    --logs PATH...      one BFS-conformal log per alpha (default: qwen3_8b's m5_alpha0{1,2,3}.txt)
    --alphas F...        (default 0.1 0.2 0.3)
    --bin_edges F...    absolute-size bin edges           (default: auto width-2 bins)
    --coverage           draw the per-alpha coverage line   (default off)
    --bar_labels          show per-bin coverage% on the bars (default off)
    --baseline_csv / --baseline_label   overlay self-sized-set series (6a output)
    --model NAME           title tag                          (default Qwen3-8B)
    --wide                two-column-width figure
    --out PATH             (default: setsize_abs_distribution_coverage_game24.png)

--- 6c. LLM-call accounting -------------------------------------------------------

    python count_llm_calls_game24.py --models qwen25_3b qwen3_8b gemma4_12b
    python count_llm_calls_winning_game24.py

Both read compare_logs_100_<model>/ per the convention above.
count_llm_calls_game24.py reports per-alpha totals (all episodes);
count_llm_calls_winning_game24.py restricts to solved puzzles and reports the
average calls per win, plus a BFS req/gen split (req = 1 per BFS node,
gen = req * n_samples).

--- 6d. Empirical coverage table --------------------------------------------------

    python table_coverage_vs_setsize_game24.py

Options: --models (default qwen25_3b qwen3_8b gemma4_12b), --bin_edges
(default 0 2 4 16), --out_txt / --out_csv (default coverage_vs_setsize_game24.txt/.csv).
Coverage% vs. absolute set-size bins, one row per method (Conf-ReAct
alpha=0.1/0.2/0.3, ReAct, ReflAct, GA-Rollback, and the self-sized-set T1/T2/T3
baseline), one section per model — reading everything from the same
compare_logs_100_<model>/ + reflexion_k3_trial*_<model>.csv files as 6b/6c.
